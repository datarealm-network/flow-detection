# 数据资产权益保护 - 网络流量监控模块需求文档（第一阶段）

## 概述
本项目旨在构建一个 Golang 实现的网络流量监控模块，用于数据资产权益保护场景。本阶段目标是在一周内完成基础的 IP 管控、配置热更新、高性能 IP/CIDR 匹配、流重组与流量统计等能力。本模块将作为开源项目结构进行设计，具有可扩展性、可维护性和良好的工程规范。

---

## 一、功能目标

### 1. 管控 IP 配置文件系统
通过独立的配置文件（YAML/JSON），支持定义需要被监控的 IP 或 CIDR 列表。当配置文件发生变化时，系统检测并实现热更新，而无需重启主进程。

**需求细则：**
- 支持 IPv4 的单 IP 与 CIDR（如 `192.168.1.1`、`10.0.0.0/24`）。
- 配置文件格式定义如下（YAML 示例）：

```yaml
enabled: true
targets:
  - type: ip
    value: "192.168.1.1"
  - type: cidr
    value: "10.0.0.0/24"
```

JSON 示例：
```json
{
  "enabled": true,
  "targets": [
    { "type": "ip", "value": "192.168.1.1" },
    { "type": "cidr", "value": "10.0.0.0/24" }
  ]
}
```

字段说明：
- `enabled`: 是否启用监控
- `targets`: 监控对象列表
  - `type`: `ip` 或 `cidr`
  - `value`: 对应 IP 或 CIDR 字符串

- 使用 `fsnotify` 或等效机制实现文件变更监控。
- 配置热更新采用无锁切换（如 `atomic.Value`），避免阻塞现有业务逻辑。
- 配置变更记录日志，包含差异信息。

---

### 2. 高性能 IP/CIDR 匹配能力
系统在处理每一个网络包时，需要快速判断其 IP 是否在管控列表中。

**需求细则：**
- 单 IP 匹配使用哈希表 `map[string]struct{}`。
- CIDR 匹配使用前缀树（IP Trie）或成熟的第三方库（如 `go-iptree`）。
- 匹配 API 需要在高并发场景下保证性能，支持每秒10万次以上匹配。
- 匹配接口如下：

```
Match(ip net.IP) bool
```

---

### 3. 流记录（Flow Aggregation）
对已获取的网络包进行流重组处理（五元组：源IP、目的IP、源端口、目的端口、协议），并按时间窗口记录指定 IP 流量。

**需求细则：**
- 生成 `FlowKey`（五元组）作为唯一标识。
- 使用 LRU 或时间轮（TimeWheel）实现流存活管理。
- 每条流记录：
  - 包数
  - 字节数
  - 起止时间
  - 应用协议（MySQL、HTTPS、FTP 等基础协议识别）
- 当流中任一 IP 属于管控列表时，将该流标记为“重要流”。
- 重要流在过期时输出到本地文件或数据库（本阶段使用 JSON 文件输出）。

## 二、系统架构
模块的整体架构如下：

```
 +-------------------+        +----------------------+
 |  config.yaml      |        |  Packet Source       |
 |  (IP/CIDR List)   |        | (pcap/dpdk/af_packet)|
 +----------+--------+        +----------+-----------+
            |                            |
     Hot Reload(fsnotify)                |
            |                            |
      +-----v------+                     |
      | MonitorSet |<--------------------+
      | atomic.Val |       Extract 5-Tuple
      +-----+------+                     |
            |                            |
      +-----v------+                     |
      |  FlowMap   |------> flush ------>+-------> Output JSON
      +------------+
```

## 四、详细需求拆解（按周计划）

### ▶ Day 1：项目初始化 + 配置模块设计
- 创建 Git 仓库结构。
- 设计配置文件 schema（支持 IP/CIDR）。
- 定义 `MonitorTable` 数据结构。
- 定义 `FlowKey`、`FlowRecord` 结构。

### ▶ Day 2：IP/CIDR 加载与匹配实现
- 加载 YAML 配置。
- 初始化精确 IP map。
- 初始化 CIDR Trie 前缀树。
- 实现 `Match()` 方法。
- 单元测试：IP、CIDR、以及不匹配情况。

### ▶ Day 3：Hot-Reload 热更新实现
- 使用 fsnotify 监听文件变化。
- 采用 atomic.Value 进行无锁结构切换。
- 日志记录：配置新增、更新、删除。
- 并发访问测试与性能验证。

### ▶ Day 4：流记录模块（FlowMap）
- 实现基于时间轮或 LRU 的 FlowMap。
- 支持新建流、更新流、删除过期流。
- 回收回调 `OnFlowExpire`。

### ▶ Day 5：流统计逻辑
- 包数统计
- 字节数统计
- 应用层协议识别：简单规则匹配
- 重要流 JSON 输出器实现

### ▶ Day 6：模块联调与压测
- 使用 pcap 文件进行回放测试。
- 验证匹配准确性
- 验证重要流输出
- 性能测试（匹配性能、流处理性能）

### ▶ Day 7：文档与交付
- 完善 README
- 添加示例配置文件
- 完整 API 文档
- 生成测试报告
