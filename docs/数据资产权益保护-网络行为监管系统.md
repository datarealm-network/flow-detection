# 网络异常流量检测系统 - 需求文档

## 1. 项目背景

在多个网络出口节点部署异常流量检测系统，用于识别异常行为、统计网络关键指标，并能够与第三方 AI/聚类分析组件联动，最终应用于安全分析、流量监控、异常检测等场景。

---

## 2. 系统总体目标

本系统需实现以下整体能力：

1. **旁路采集网络流量**：不影响正常业务的前提下获取流量镜像数据。
2. **高性能解析流量**：能够以高吞吐量处理原始网络数据（例如 pcap、AF\_PACKET、DPDK）。
3. **提取关键特征**：从网络包中提取五元组、协议字段、流量统计等指标。
4. **规则、阈值、无监督算法检测**：无需依赖预训练模型，即可进行基础异常检测。
5. **支持第三方算法组件对接**：以 API 方式向外提供数据接口或算法调用接口。
6. **海量数据入库能力**：支持分布式批量写入（如 ClickHouse、MySQL等）。
7. **可扩展性**：能够横向扩展多个采集节点、多个分析节点。

---

## 3. 模块化架构设计

### 3.1 设计理念

本系统采用**高度模块化**的架构设计，各模块通过**标准化接口**进行交互，具备以下核心优势：

**1. 技术演进能力**
- 每个模块可独立升级，无需重构整个系统
- 支持技术栈替换：如从 AF_PACKET 升级到 DPDK，只需更换采集模块
- AI 算法模块预留标准接口，可由专业团队后续开发集成

**2. 横向扩展能力**
- 采集节点可按需水平扩展（1个→10个→100个）
- 存储层支持分布式集群部署
- 分析模块支持多实例并行处理

**3. 松耦合设计**
- 模块间仅通过消息队列（Kafka）或API通信
- 单个模块故障不影响其他模块运行
- 便于团队分工协作开发

**4. 接口标准化**
- 定义清晰的数据格式（JSON/Protocol Buffers）
- RESTful API 和 gRPC 双协议支持
- 版本管理机制，支持平滑升级

### 3.3 核心模块功能说明

#### 模块1：流量采集层（Packet Capture Module）

**核心价值：** 无侵入式获取网络流量，保证业务零影响

**主要功能：**

- **旁路镜像接收**：从交换机镜像端口或 TAP 设备获取流量副本
- **高性能抓包**：使用零拷贝技术，减少内核态与用户态数据复制
- **内核级过滤**：利用 BPF/eBPF 机制在内核空间尽早丢弃无关流量，避免无效数据进入用户态，大幅节省 CPU
- **多节点部署**：支持多个采集节点独立运行，横向扩展

**技术演进路径：**

```
初期：AF_PACKET（易实现，性能满足 1-10Gbps）
   ↓
中期：PF_RING（性能优化，支持 10-40Gbps）
   ↓
高级：DPDK（极致性能，支持 40-100Gbps）
```

**接口输出：**
- 数据格式：原始以太网帧
- 传输方式：内存 Ring Buffer（进程间零拷贝）
- 性能指标：丢包率 < 0.1%

**行业优势：**
- ✅ 不修改网络拓扑，部署简单
- ✅ 技术栈可按需替换，投资保护
- ✅ 支持多种抓包技术，适应不同场景

#### 模块2：数据解析层（Parser & Feature Extraction）

**核心价值：** 将海量原始数据包转换为高价值的流特征，实现数据降维

**主要功能：**
- **多层协议解析**：支持 L2-L7 层协议（以太网、IP、TCP/UDP、HTTP/DNS/TLS）
- **流聚合技术**：将数千个包聚合为一条流记录，数据量减少 10000 倍
- **智能采样策略**：首部 10 包（First 10 packets）深度解析，后续包智能采样，节省 98% CPU
- **丰富特征提取**：提取 60+ 维特征（网络层、传输层、应用层、时序特征）

**数据压缩效果：**
```
输入：1Gbps 网络 = 100万包/秒 = 10.8TB/天（原始包）
   ↓ 流聚合
输出：1000流/秒 = 100万流/天 = 1GB/天（流记录）
压缩比：10800:1
```

**智能采样策略：**
- 新流前 10 包：完整解析（识别协议）
- 短流（<50包）：全部解析（高信息密度）
- 稳定流：每 100 包采样 1 个（持续监控）
- 大象流（>100MB）：每 1000 包采样 1 个（避免资源耗尽）

**接口输出：**
- 数据格式：`FlowRecord` 结构（JSON/Protobuf）
- 包含字段：60+ 维特征
- 传输方式：Kafka 消息队列 / 直接入库
- 性能指标：CPU 占用 < 20%（单核处理 10 万流/秒）

**行业优势：**
- ✅ 解决海量数据存储难题
- ✅ 保留关键信息，丢弃冗余数据
- ✅ 为 AI 分析提供高质量特征

#### 模块3a：实时分析层（Rule & Detection Engine）

**核心价值：** 基于规则和统计算法的实时异常检测，无需依赖 AI 模型

**主要功能：**
- **规则引擎**：支持灵活配置的检测规则
  - 阈值类：QPS 超限、流量突增、连接数异常
  - 模式类：端口扫描、SYN Flood、DNS 隧道
  - 黑白名单：IP/域名/端口黑白名单
  
- **统计算法**：轻量级异常检测
  - 3-Sigma 异常检测（基于均值和标准差）
  - MAD（中位数绝对偏差）检测
  - 滑动窗口统计（1分钟/5分钟/1小时）
  
- **实时告警**：毫秒级响应
  - 异常流立即标记
  - 告警事件写入 MySQL
  - 支持告警抑制和聚合

**规则配置示例：**
```yaml
rules:
  - name: "端口扫描检测"
    condition: "unique_dst_ports_per_src_ip > 100 in 60s"
    severity: HIGH
    action: alert
    
  - name: "SYN Flood 检测"
    condition: "tcp_syn_count > 1000 AND tcp_syn/tcp_ack > 3 in 10s"
    severity: CRITICAL
    action: alert
    
  - name: "DNS 隧道检测"
    condition: "dns_query_length > 50 AND dns_subdomain_count > 5"
    severity: MEDIUM
    action: alert
```

**接口输出：**
- 数据格式：`AlertEvent` 结构
- 传输方式：写入 MySQL + 推送 Kafka
- 性能指标：处理延迟 < 10ms

**行业优势：**
- ✅ 无需训练数据，开箱即用
- ✅ 规则灵活可配，适应业务变化
- ✅ 低延迟响应，满足实时需求

| **流式层** | Kafka | 实时流特征 | 24小时 | AI模型消费 |
| **冷数据层** | S3/MinIO | 归档数据 | 永久 | 合规审计 |

**主要功能：**

**接口输入：**
- 流记录批量写入接口

**性能指标：**
- ClickHouse 写入：10 万行/秒

**行业优势：**
- ✅ 分层存储，成本优化

- ✅ 高性能查询，支持复杂分析

#### 模块4：AI 集成层（AI Integration API）

**核心价值：** 提供标准化接口，支持第三方 AI 算法组件对接

**设计理念：**
- **接口优先**：先定义接口标准，AI 算法由专业团队后续开发
- **技术无关**：支持任何编程语言（Python/Java/C++）实现的算法
- **松耦合**：AI 模块故障不影响主系统运行
- **可演进**：支持算法版本升级、A/B 测试、热切换

**主要功能：**

**1. 特征推送接口**
```
系统 → AI模型
方式：gRPC Stream / REST API / Kafka
格式：FlowRecord（JSON/Protobuf）
频率：批量推送（100-1000条/批）
```

**2. 结果回调接口**
```
AI模型 → 系统
方式：Webhook / Kafka
格式：JSON（聚类ID、分类标签、异常分数）
处理：写入数据库 + 触发告警
```

**3. 批量查询接口**
```
AI模型 → 系统
方式：REST API
功能：查询历史流记录用于模型训练
```

**支持的 AI 算法类型：**

| 算法类型 | 应用场景 | 是否需要训练数据 | 输出结果 |
|---------|---------|----------------|----------|
| **聚类** | 告警降噪、模式发现 | ❌ 无监督 | 簇ID、簇标签 |
| **分类** | 攻击类型识别 | ✅ 有监督 | 类别标签、置信度 |
| **异常检测** | 零日攻击发现 | ❌ 无监督 | 异常分数 |
| **威胁情报** | 恶意IP/域名匹配 | ✅ 需要情报库 | 威胁等级 |
| **行为分析** | 用户画像、UEBA | ✅ 需要基线 | 行为分数 |

**接口标准定义：**

```protobuf
// gRPC 接口定义（示例）
service AIIntegration {
  // 批量推送流特征
  rpc PushFlowFeatures(stream FlowFeaturesBatch) returns (PushResponse);
  
  // 查询历史流记录
  rpc QueryFlows(FlowQuery) returns (FlowRecords);
  
  // 接收AI模型的检测结果
  rpc ReportResults(DetectionResults) returns (AckResponse);
}

message FlowFeaturesBatch {
  repeated FlowFeature features = 1;  // 批量特征
  int64 timestamp = 2;
  string node_id = 3;
}

message DetectionResults {
  string result_type = 1;  // clustering/classification/anomaly
  repeated Result results = 2;
}
```

**性能保障：**
- API 超时：< 100ms
- 批量大小：100-1000 条
- 熔断机制：失败率 > 20% 自动降级
- 限流保护：QPS 限制 1000

**行业优势：**
- ✅ 接口标准化，降低集成难度
- ✅ 技术栈灵活，支持多种 AI 框架
- ✅ 性能可控，避免影响主系统
- ✅ 预留扩展，未来可集成多种算法

**演进路径：**
```
阶段1（当前）：接口设计完成，数据格式定义
   ↓
阶段2（3个月后）：集成基础聚类算法（K-Means）
   ↓
阶段3（6个月后）：集成分类算法（随机森林）
```

#### 模块6：告警管理（Alert Management）

**核心价值：** 闭环管理告警全生命周期

**主要功能：**
- **告警聚合**：相似告警自动归类（基于聚类）
- **工单系统**：告警→工单→处理→关闭
- **通知分发**：多渠道通知（邮件、短信、企业微信）
- **处理流程**：分配、跟踪、审核、归档

**告警生命周期：**
```
NEW（新建）→ ASSIGNED（已分配）→ IN_PROGRESS（处理中）
   → RESOLVED（已解决）→ CLOSED（已关闭）
   → FALSE_POSITIVE（误报）
```

**行业优势：**
- ✅ 闭环管理，提高处理效率
- ✅ 多渠道通知，不遗漏告警
- ✅ 统计分析，优化检测规则
